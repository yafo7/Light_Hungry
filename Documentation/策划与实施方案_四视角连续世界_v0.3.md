# Light Hungry／食光：四视角连续世界策划与实施方案

版本：v0.3 · 2026-10-27  
依据：10 月 26 日讨论纪要、双方后续讨论及 10 月 27 日确认。  
用途：两人共同推进项目的工作方案。本文中的“建议”“后续”不代表已经实现；工程实际进度应以代码和 Unity 验收为准。

## 1. 游戏定位

《食光》是一款结合视角旋转、平台移动和光线反射的空间解谜游戏。玩家操纵一只以光为食的小怪物，寻找光源、操作机关、调整或搬动镜子，将光引导到无法移动的野兽身边。

核心表达：**摄像机拍摄到的，不等于世界的全部。**

光源、镜子、平台、机关、角色与野兽处于同一个连续世界。切换视角不会重新生成地图，不会使物体凭空换位置，也不会重置机关。

两条相互配合的解谜线：

| 解谜线 | 玩家要解决的问题 |
| --- | --- |
| 移动路线 | 怎样利用其他方向的平台，到达原先无法到达的装置？ |
| 光线路线 | 怎样调整不同方向的镜子，让光绕过遮挡、改变方向并照到野兽？ |

核心循环：观察目标 → 发现道路或光路的阻碍 → 旋转视角获取信息 → 到达装置并操作 → 检查变化 → 完成喂食。

角色成长主要来自玩家对空间的理解，而非叠加大量主动能力。

## 2. 四个二维玩法视角

四个视角共享同一个关卡和一套对象，不是四张互相独立的地图。

| 视角 | 本阶段调试键 | 相对默认视角的方位 |
| --- | --- | --- |
| 默认面 | 1 | 0° |
| 对面 | 2 | 180° |
| 左面 | 3 | 摄像机位于默认观察中心左侧 |
| 右面 | 4 | 摄像机位于默认观察中心右侧 |

键位采用绝对目标：例如无论当前在哪里，按 1 都回默认面。主键盘与数字区均应支持。以后正式切面方式另行设计。

稳定游玩采用四个正交方向；中间角度仅作为连续旋转过程，不允许自由停留。一个关卡可以只开放一个或两个视角，后续逐步开放四个方向。

空间认识递进：单视角理解眼前光路 → 双视角发现画外世界 → 四视角理解整个房间。

## 3. 真实连接与投影通行的区别

首版采用真实空间连接。例：L 形平台，正面沿 X 行走到转角，转到侧面后沿 Z 前进。平台真实连通，角色保持世界位置。

“空间不相连但投影对齐后就能走”需要额外系统：二维碰撞代理、支撑面归属、深度转换、多平台重叠选择和交互一致性。它不是旋转摄像机自动带来的结果，留作后续独立实验。

参考 FEZ 的四个二维视角探索空间体验，不声称使用其内部实现方案。

## 4. 操作和统一规则

| 输入 | 功能 |
| --- | --- |
| A / D | 沿当前画面左右移动 |
| W / S | 镜头上下观察，不负责前后移动 |
| 空格 | 世界竖直方向跳跃 |
| E | 开关交互；拾取／放下属于后续搬运系统 |
| 1 / 2 / 3 / 4 | 默认／对面／左面／右面，当前调试方式 |
| R | 重开 |
| Esc | 暂停与恢复 |

初版只在站稳时接受视角切换。过渡中暂停角色、机关和物理模拟，完成后恢复。切换前后角色世界位置保持一致；输入方向改为新视角的画面左右。切面不重置谜题。

看不见的对象仍然存在并参与解谜。仅转动摄像机不改变光的真实方向或命中结果。交互依据实际空间距离，不能隔着深度操作投影重叠的物体。

角色自身反光、储光和吐光暂不作为正式主线的必要能力。现有实验场景中的这些能力可保留用于对照，不代表新策划依赖它们。

过关条件：光命中野兽身边清楚可见的接光区域，产生进食反馈，达到可配置接光时长。原型可以沿用已有接光计时；正式关卡完成流程后续统一。

## 5. 基础物体与交互

| 物体 | 职责 | 首版范围 |
| --- | --- | --- |
| 小怪物 | 移动、跳跃、交互 | 必需 |
| 野兽 | 接光、进食、完成反馈 | 必需 |
| 光源 | 固定世界方向发光 | 必需 |
| 平面镜 | 按镜面法线反射 | 必需 |
| 压力按钮 | 踩踏触发，松开按配置恢复 | 必需 |
| 主动开关 | E 切换状态或执行动作 | 必需 |
| 轨道／滑轮 | 移动平台或镜子 | 复用已有思路 |
| 可搬运镜子 | 携带到需要的位置再布置 | 后续实现 |
| 木箱 | 挡光、压按钮、落脚 | 按关卡需要 |
| 透镜、水杯 | 聚焦或折射 | 暂缓 |

镜子改变方向属于反射；透镜和水杯涉及折射。先验证反射与多视角组合。

按钮只发出状态，镜架、轨道等装置响应状态，不把某关逻辑写死在按钮里。

搬运建议：一次一个，E 拾取、E 放下；携带时固定在携带点，放下检查空间；镜子可搬运时收起，放下后展开，角度由镜架、放置点或配套开关确定。第一批可使用清楚的放置点降低摆放精度要求。现有按住 E 推拉木箱不等于拾取／放下。

## 6. 摄像机与角色的技术方案

### 6.1 共享世界与观察中心

一个 Unity Scene 对应一个关卡，包含所有平台、光源、镜子和机关。摄像机围绕关卡观察中心转动，不是站在房间中心原地扭头。

推荐结构：

```text
Level
├─ World：平台、墙、镜子、光源、机关、野兽
├─ Player：真实位置、碰撞与移动
├─ CameraRig
│  └─ MainCamera：正交投影
└─ LevelSystems
```

摄像机保持固定观察距离与正交尺寸，沿世界 Y 轴平滑旋转。90° 转动约 0.35～0.5 秒，180°可适当延长，最终以试玩决定。

一次旋转事务：检查站稳及暂停状态 → 保存世界位置、暂停模拟 → 连续旋转 → 更新运动方向和深度约束 → 恢复模拟。旋转期间的新请求应有一致的处理，不得叠加多条转动协程。

### 6.2 世界坐标与投影

同一个世界位置从不同方向观察，画面坐标自然改变。不要把角色强制移动到旧屏幕位置。

令 P 为物体世界位置，C 为观察中心，R 为摄像机向右，U 为世界向上：

```text
u = Dot(P - C, R)
v = Dot(P - C, U)
```

转动时 R 改变、P 不变。Unity 摄像机完成实际渲染投影。

### 6.3 角色运动平面

默认面按 D 沿 +X；对面沿 -X；摄像机位于默认面左侧时沿 -Z；位于右侧时沿 +Z。这里“左／右面”指摄像机相对默认观察中心的位置。跳跃始终沿 +Y。

XY 游玩时锁定角色当前 Z；ZY 游玩时锁定角色当前 X，不能强制吸到 X=0 或 Z=0。使用三维刚体时按稳定视角配置约束并冻结自身旋转。

二维角色 Sprite 单独作为显示子节点面向摄像机；物理根节点保持真实世界位置。角色翻转精灵决定左右朝向。镜面不能随镜头做 billboard，它的真实方向决定反射。

### 6.4 原单面实验场景的适配

保留用户已有摆放和新增对象，采用场景内增量适配。平台需要有厚度，才能在旋转时显示连续结构。角色与部分装饰使用二维显示适配；镜子真实朝向保留。环境外壳只能处理装饰遮挡，不能无提示隐藏真正的障碍。

原始 prefab 和单面实现保留，避免重建场景或批量覆盖美术资源。二维物理和三维物理不同，不能仅旋转现有 Rigidbody2D 就宣称完成新运动平面。

## 7. 世界空间光路

光线按世界位置和方向传播；转镜头只改变观察结果。

示例：光源沿 +X → 镜子转向 +Z → 第二镜子向上 → 野兽接光。

推荐追踪：Physics.Raycast 查询三维碰撞 → 普通障碍停止 → 镜子按真实法线 Vector3.Reflect → 接光区更新状态。保留反射次数、总距离限制和光束显示对象复用，防止无限反射。

当前二维光路的 Vector2、Physics2D 查询需要空间适配；不把跨面传播实现成随意传送或无缘由拐弯。画面上光和镜子重合不保证实际相交。

## 8. 程序模块与工程衔接

| 模块 | 职责 |
| --- | --- |
| 视角控制 | 当前绝对视角、旋转事务、镜头观察 |
| 角色运动 | 跳跃、当前方向、深度约束、地面检测 |
| 角色显示 | 动画、面向摄像机、左右朝向 |
| 空间适配 | 现有单面场景的厚度、碰撞与显示适配 |
| 交互控制 | 实际距离筛选、E 交互 |
| 搬运控制 | 后续拾取、携带、放下检测 |
| 光路求解 | 世界射线、反射、接光判定 |
| 关卡控制 | 状态、完成与重开 |

现有输入、动画、美术、镜子预设状态、野兽进食、按钮联动和光路分段思路可复用。角色物理、地面检测、光线查询以及触发需要适配三维空间。新增原型不应抹掉原有场景改动。

## 9. 代表性关卡与整体递进

先验证一个房间：起点拾取镜子 → 沿平台走到转角 → 转 90°发现另一条道路 → 到达镜架放置镜子 → 将光反射到另一空间方向 → 野兽进食。

验证目标：旋转帮助到达新区域；搬运连接移动与光路；不同视角的光路一致；玩家理解“它一直在那里，只是刚才没看清”。搬运完成前，可用固定镜架代替验证镜头。

| 阶段 | 内容 |
| --- | --- |
| 1～3 关 | 单视角移动、按钮、镜子和接光 |
| 4～5 关 | 双视角道路，理解新的移动方向 |
| 6～8 关 | 双视角光路、搬运和跨方向机关 |
| 9～12 关 | 四视角综合路线与光路 |
| 13～15 关 | 多步骤规划；视错觉有余力再独立验证 |

15 关是目标，优先保证完整递进与质量，必要时先形成 8～10 关的可玩版本。

## 10. 美术、协作与计划

风格：颜色干净、线条直接、较粗外轮廓、克制的油画色块。角色和野兽沿用透明 PNG 动画。平台用简单几何提供厚度；镜面和支架应表达真实朝向；光束、命中点和反射点优先保证清晰。

程序与引擎由用户负责；同伴负责整体画风、角色、环境、装置和故事表达；共同设计谜题并试玩。每关指定主要搭建者，尽量避免同时编辑同一 Scene。先统一整体样张，再批量制作素材。

不在游戏画面添加开发说明、调试标签或未要求的教学 UI。玩法和验收说明在 Codex 中解释。

## 11. 本阶段验收

- 1 默认、2 对面、3 左面、4 右面，主键盘与数字区一致。
- 四次旋转及反复切换，角色和物体位置无漂移，机关状态不重置。
- 过渡平滑，画面比例稳定；侧面角色可见，平台具有厚度。
- A/D 对应画面左右，跳跃沿世界向上；切换本身不瞬移角色。
- 仅旋转镜头，光路实际命中不变；面内旧交互继续可验证。
- 暂停、切换中输入和重开行为一致，无卡在暂停状态的问题。
- 编译、运行验证与四面实际截图检查一起完成。
- 不将暂未实现的搬运、投影通行、正式关卡流程描述为已完成。
