# 第二关：倒扣陶盆 · 露珠折射分层 v08

本版用叶片上残留的透明露珠取代镜片。阳光穿过露珠后偏折，穿过封堵暗渠入口的碎石缝，抵达缝后的落脚台。第二关没有食光兽身体部分；人物继续作为独立 3D 角色。

双击 `index.html` 查看真实图层叠合。右侧可逐层开关；底部可以仅显示背景、仅显示前景、放大下半部、显示角色尺度和光路。`分层总览.png` 是预览页面截图，`叠层预览.png` 是实际叠合结果。

## 定位与 Unity 搭建

PNG 文件均为 1774 × 887。生成的叶片和碎石单件有位置、比例漂移，因此已在预览中校准；不能把所有 PNG 直接以相同 Transform 重叠。`layer-manifest.json` 和 `layer-data.js` 保存同一份定位数据；`registered-scene.svg` 引用这些原文件并按同样参数排列。

坐标从画布左上角开始，x 向右、y 向下。矩阵为 `[scaleX, 0, 0, scaleY, offsetX, offsetY]`：

| 图层 | scaleX | scaleY | offsetX / px | offsetY / px |
| --- | ---: | ---: | ---: | ---: |
| 背景 | 1 | 1 | 0 | 0 |
| 地面 | 1 | 1.1 | 0 | -23 |
| 叶片露珠 | 0.41 | 0.41 | 341 | 265 |
| 碎石 | 0.61 | 0.61 | 546 | 252.1 |
| 光线 | 1 | 1 | 0 | 0 |

可在 Unity 中把这些图片导入为 Sprite，统一使用左上角 Pivot `(0,1)`。设定任意统一的 PPU 值 P，以及地面参考原点 y0 后，每层位置为 `(offsetX/P, (y0-offsetY)/P)`，缩放按表，Sorting Order 按图层顺序。预览中的角色参考高度为 63 px，只用于这张图的比例观察，不替代后续灰盒的统一世界尺寸。

地面碰撞应简化苔地与台阶的顶缘，不描摹每片叶子；碎石上、下岩块分别做碰撞，保留缝隙。光线的视觉光晕可以宽于光核碰撞体。不要仅凭 PNG 透明度宣称实体一定不能绕行：跳跃绕过石堆、缝后恢复身体的净空、台阶的实际行走都需要在 Unity 中测试。

## 化光规则

- 用户已确认：这是全局能力，在有效光中站定三秒，身体边缘发亮、光晕扩大，最后变成一个光粒子。
- 用户已确认：光态由玩家控制沿光线前后移动，可以停留、回退；不是自由飞行。
- 本版选择：露珠初始已对准；沿折射光穿过真实小缝，碎石不消失。
- 缝后自动恢复、手动恢复键、光路中断回退等仍沿用 v07 的“建议项”身份，尚未作为用户已确认规则。

SVG 的光路节点为 `(877,61) → (789,401) → (790,429) → (1370,713.2)`，其中中间两点用于表现入滴与出滴。这是一条**为关卡构图编排的折射路径**，不是经过斯涅尔定律、水滴曲面与遮挡验证的光学模拟。实际接入时应让叶片边缘、水滴表面法线和出射路径一起配合，避免光穿过不透光的叶片实体；美术预览不验证这一物理细节。

## 验证与来源

- 五层画布尺寸一致；四层前景均含真实 alpha 通道。
- 在对齐后的石缝中，以直径 5.04 px 的光核采样了 7,497 个点，没有达到 alpha 128 的阻挡点；最大 alpha 为 6。此项只证明本版图片的窄缝透明，不代表碰撞系统已经实现。
- 浏览器检查：五张图成功加载；背景/前景开关、近景查看、光线强度控制正常，未记录页面错误。
- 已查看叠合图和近景尺度图，光路沿透明石缝贯通。报告在 `QA/`。
- 水彩图由内置 `image_gen` 编辑和重建，无 CLI/API 回退。全部提示词在 `generation-prompts.json`。光线 SVG 是另作的可编辑矢量层，PNG 由它导出；生成的光线氛围草稿保留在 `References/`，未用于最终叠合。
- 本版是**分层重建**，不是原图无损抠图；原始 v07 和生成原文件保留。除矢量光线外，PNG 源文件没有通过脚本抠图或改画。位置校准由预览和清单完成。

这轮交付为美术图层与预览；没有修改 Unity 工程，没有新增第二关运行场景，也没有把图片检测当作运行验证。
